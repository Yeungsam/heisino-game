# 微信小游戏 UI 安全区规范

版本：2.0.0
最后更新：2026-10-20
适用范围：全部横屏页面、弹窗、HUD、文字、按钮和触摸热点

## 1. 基本原则

游戏场景和视觉背景始终铺满物理屏幕，不因微信胶囊、手机前置摄像头/刘海/灵动岛或底部手势栏而缩小整张画面。

系统占用区及其保护间距内不得放置：

- 标题、Logo、玩家状态、回合数、生命值、货币或倒计时。
- 按钮、卡牌、拖拽目标或其他有效操作区。
- 必须阅读的提示、规则和结算信息。
- 视觉上看似可以点击的伪按钮或 UI 图形。

系统占用区可以显示不承载交互或关键信息的场景、环境、光影和人物插画。

## 2. 运行时依据

客户端使用微信运行时提供的信息计算内容安全边界：

- `wx.getWindowInfo()`：读取窗口尺寸、像素比和设备 `safeArea`。
- `wx.getMenuButtonBoundingClientRect()`：读取右上角胶囊按钮位置。
- `safeArea.left/right`：避开横屏状态下位于左右侧的摄像头或刘海区域。
- `safeArea.bottom`：避开底部手势条和系统操作区。

如果开发者工具或低版本运行环境返回无效胶囊数据，客户端启用保守回退：顶部至少保留短边约 `11%` 的系统保护区，并在内容边界内额外保留 `8–18` 逻辑像素间距。

## 3. 双层画面结构

```text
物理屏幕
├─ 全屏视觉层：场景、环境、插画和不承载关键信息的装饰
└─ 内容安全层：标题、文字、HUD、卡牌、按钮和触摸热点
```

- 全屏视觉层始终使用物理屏幕坐标绘制，按 `cover` 方式填满屏幕。
- 内容安全层根据设备和胶囊位置等比调整，不得进入系统占用区。
- 背景素材不得烘焙标题、文字、按钮或伪 UI；这些内容必须由客户端在内容安全层单独绘制。

## 4. 内容安全边界算法

1. 取得窗口逻辑宽高和设备 `safeArea`。
2. 以屏幕短边的 `2.5%` 计算内容间距，并限制在 `8–18` 逻辑像素。
3. 内容左、右、下边界在设备 `safeArea` 内保留上述间距。
4. 内容顶部不得高于“胶囊按钮底边 + 内容间距”。
5. 胶囊数据无效时采用保守顶部回退区。
6. 信息和交互内容等比适配至内容边界中；全屏视觉层不参与此变换。
7. 所有触摸坐标使用同一变换的逆矩阵转换回逻辑坐标，保证视觉与热点一致。

## 5. 页面执行要求

| 页面/区域 | 执行要求 |
|---|---|
| 加载页 | 背景全屏；进度条和加载文字位于内容安全层 |
| 首页 | 角色和场景全屏；Logo、开始按钮及其他入口独立绘制并避开系统区域 |
| 战备页 | 背景全屏；NPC 对话、仓库卡牌、背包格和底部按钮位于内容安全层 |
| 匹配页 | 背景全屏；席位、倒计时、取消和单人测试按钮完整可见 |
| 游戏 HUD | 场景全屏；顶部回合/HP/资产信息整体位于胶囊保护线下方 |
| 地图与背包 | 左右边界避开横屏摄像头/刘海；所有节点与物品热点同步调整 |
| 底部操作 | 锁定移动、下一回合、开始匹配等按钮高于底部手势保护线 |
| 弹窗/结算 | 背景保持全屏；主要信息和关闭/确认操作位于内容安全层 |

## 6. 自动化验证矩阵

当前测试覆盖：

- 无刘海横屏设备 + 正常胶囊数据。
- 左右安全区收紧的横屏摄像头设备。
- 存在底部手势区域的设备。
- 胶囊数据无效时的保守回退。
- 屏幕坐标与逻辑触摸坐标的往返一致性。

执行：

```bash
npm run check
```

## 7. 新页面接入约束

- 新页面必须分离全屏视觉层和内容安全层。
- 场景背景必须铺满物理屏幕，不得跟随内容安全变换缩小。
- 标题、文字、HUD、卡牌、按钮和热点必须使用内容安全坐标。
- 背景素材必须是纯场景素材，不得内置可读文字或可操作元素。
- 新增任何浮层、广告、活动入口或临时调试按钮时，必须复查系统占用区。
- 设备截图验收至少包括首页、页面主体和一个底部操作状态。
- 如修改内容间距或回退尺寸，必须同步更新本文、产品决策台账和安全区自动化测试。
