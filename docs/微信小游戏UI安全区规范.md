# 微信小游戏 UI 安全区规范

版本：1.0.0
最后更新：2026-10-20
适用范围：全部横屏页面、弹窗、HUD、文字、按钮和触摸热点

## 1. 基本原则

微信小游戏的系统胶囊按钮、手机前置摄像头/刘海/灵动岛区域以及底部手势操作栏均属于系统占用区。系统占用区及其保护边距内不得放置：

- 按钮、卡牌、拖拽目标或其他有效操作区。
- 回合数、生命值、货币、倒计时等有效状态信息。
- 必须阅读的标题、提示、规则和结算信息。
- 视觉上看似可以点击的伪按钮。

允许延伸到系统占用区的内容仅限不承载信息的装饰背景、渐变、纹理和场景边缘。

## 2. 运行时依据

客户端使用微信运行时提供的以下信息计算安全区：

- `wx.getWindowInfo()`：读取窗口尺寸、像素比和设备 `safeArea`。
- `wx.getMenuButtonBoundingClientRect()`：读取右上角胶囊按钮位置。
- `safeArea.left/right`：避开横屏状态下位于左右侧的刘海或前置摄像头区域。
- `safeArea.bottom`：避开底部手势条和系统操作区。

如果开发者工具或低版本运行环境返回无效胶囊数据，客户端启用保守回退：顶部至少保留短边约 11% 的系统区域，再叠加基础出血边距。

## 3. 双层画布结构

```text
物理屏幕
├─ 出血背景层：铺满全屏、压暗，仅作装饰
└─ 安全内容层：整体等比缩放并居中
   ├─ 所有清晰场景画面
   ├─ 所有文字与状态
   ├─ 所有按钮与卡牌
   └─ 所有触摸/拖拽热点
```

背景仍可铺满屏幕，避免出现突兀黑边；但安全内容层之外的背景统一压暗，确保系统按钮下方不会出现可误认为有效信息的清晰内容。

## 4. 安全内容区算法

1. 取得窗口逻辑宽高和设备 `safeArea`。
2. 以屏幕短边的 `2.5%` 计算基础出血边距，并限制在 `8–18` 逻辑像素。
3. 内容左、右、下边界分别向 `safeArea` 内收一个出血边距。
4. 内容顶部不得高于“胶囊按钮底边 + 出血边距”。
5. 胶囊数据无效时，采用保守顶部回退区。
6. 将原有逻辑画布等比缩放到内容边界中，剩余空间居中分配。
7. 所有触摸坐标使用相同变换的逆矩阵转换回逻辑坐标，保证视觉与热点一致。

缩放采用等比 `min(widthScale, heightScale)`，不得分别拉伸宽高。

## 5. 页面执行要求

| 页面/区域 | 安全区要求 |
|---|---|
| 加载页 | 进度条和加载文字必须位于安全内容层 |
| 首页 | 标题、开始按钮、其他入口均不得进入胶囊区 |
| 战备页 | NPC 对话、仓库卡牌、背包格和底部按钮全部位于安全内容层 |
| 匹配页 | 席位、倒计时、取消和单人测试按钮必须完整可见 |
| 游戏 HUD | 顶部回合/HP/资产信息整体低于胶囊保护线 |
| 地图与背包 | 左右边界避开横屏刘海；所有节点与物品热点同步收缩 |
| 底部操作 | 锁定移动、下一回合、开始匹配等按钮高于底部手势保护线 |
| 弹窗/结算 | 主要信息和关闭/确认操作不得延伸到系统占用区 |

## 6. 自动化验证矩阵

当前测试覆盖：

- 无刘海横屏设备 + 正常胶囊数据。
- 左右安全区收缩的横屏刘海设备。
- 存在底部手势区域的设备。
- 胶囊数据无效时的保守回退。
- 屏幕坐标与逻辑触摸坐标的往返一致性。

执行：

```bash
npm run check
```

## 7. 新页面接入约束

- 新页面必须在全局安全内容变换内绘制，不得自行重置为物理屏幕坐标。
- 只有纯装饰背景允许使用物理全屏坐标。
- 新增任何浮层、广告、活动入口或临时调试按钮时，必须复查系统占用区。
- 设备截图验收至少包括首页、该页面主体和一个底部操作状态。
- 如修改出血比例或回退尺寸，必须同步更新本文、产品决策台账和安全区自动化测试。
