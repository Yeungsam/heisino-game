# 多人联机五轮自动化验收

基线 `bcc85fa`，分支 `codex/multiplayer-single-player`。

按多人 PRD、已确认的对局规则，以及项目的接口、数据和页面联合验收要求执行。每轮独立启动回环 HTTP 服务，使用真实账号路由、游戏引擎与独立模拟身份。界面测试运行生产 Canvas 渲染和触控处理代码，检查绘制内容、按钮和实际触点。使用内存仓库与可控时钟，覆盖网络延迟和十分钟边界。测试数据与微信和 CloudBase 线上环境隔离。

## 第 1 轮 · 码头大厅与开局

- 覆盖建房、三人上限、退出不扣仓、房主转让、开局权限、游戏中列表折叠及三个账号的扣仓流水。
- 首跑时，列表显示 3/3 后已有玩家离开，客户端仍拦截加入，未向服务端查询空位。
- 已修复。点击待开始的房间时始终请求服务端，真实满房仍显示明确提示。复测 4/4 通过。

## 第 2 轮 · 移动与共享回合

- 覆盖三端的合法移动、隐藏对手位置、提交后等待、移动超时原地停留，以及搜索阶段超时推进。
- 首跑时，移动倒计时归零后仍绘制可点选格子和确认按钮，过期输入会发往服务端。
- 已修复。截止后撤掉移动热区，显示同步状态；旧帧上的确认触点也会重新校验时限。复测 3/3 通过。

## 第 3 轮 · 三人同房、搜索与触控

- 三端沿合法路径同回合进同一房间，检查胜者、战败结算和独立搜索方；从搜索界面拖入胜者背包，并尝试由第三人拾取同一实例。
- 首跑时，搜索拖拽中跨过回合截止，手指在新地图的确认按钮上抬起会替玩家提交移动。
- 已修复。观察区域或回合切换时取消搜索手势并吞掉该次抬手。正常拖拽、背包堆叠、水波纹和离开按钮优先级均复测通过（4/4）。

## 第 4 轮 · 断线、重连与前后台切换

- 覆盖一人中断时其余玩家继续、十分钟内恢复当前房间、恰满十分钟个人失败，以及多次前后台切换。
- 首跑时，玩家已从失败结算返回首页时，第二条迟到的恢复响应会重新打开结算，造成空白页面。
- 已修复。回调必须仍属于当前对局页面且客户端处于前台才可切换页面。复测 5/5 通过。

## 第 5 轮 · 独立撤离、连续开局和个人结算

- 实际触控走到撤离点，验证拾取物资和原战备只返仓一次，金币不变，另一名玩家继续；再从结算进入单人模式。
- 首跑时，重发上一局的已读确认会把新一局的结算也标为已读，冷启动直接跳过新结算。
- 修复后，客户端发送当前结算 ID，服务端只确认对应结算。旧版模式仍支持原确认方式。复测 4/4 通过。

## 汇总

- 五轮均先复现、记录和修复，再复测通过后进入下一轮。
- `npm run check` 通过 145/145。五个联机界面用例连续跑 10 次，共通过 50 次。
- 在本机 Chrome 用两个独立账号抽查 667×375 和 812×375 的实际 Canvas，核对码头成员、房主开局按钮、地图和提交后的等待状态。
- 验收范围为本机模拟。CloudBase 和微信真机的网络、数据库及视觉表现需在部署后验证。

`node --test --test-name-pattern '第1轮' tests/multiplayer-ui.test.js` 可单独重跑第 1 轮。将匹配名换成对应轮次即可重跑其他轮次。
