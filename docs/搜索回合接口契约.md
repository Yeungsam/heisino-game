# 搜索回合接口契约

版本：2.0.0

日期：2026-10-26

状态：M2.4 当前实现

## 1. 权威边界

搜索服务是房间区域、区域物资、玩家搜索背包、按玩家曝光状态、50 秒期限和访问状态的权威来源。客户端可以播放拖拽和搜索水波纹动画，但只有收到服务端成功快照后才能确认拾取或丢弃。

当前迭代仅将搜索链路服务化；匹配、移动、遭遇和机器人仍使用客户端测试状态机。接口使用 `gameId`、`playerId`、`turn` 和 `roomNodeId` 预留后续完整三人对局接入。

## 2. 状态模型

物品状态：

| 状态 | 含义 |
|---|---|
| `HIDDEN` | 位于房间且尚未向该玩家曝光 |
| `EXPOSED` | 已曝光但仍留在房间 |
| `IN_INVENTORY` | 已进入玩家背包 |
| `DROPPED` | 玩家主动或战败后留在房间 |
| `DESTROYED` | 已销毁，不再参与搜索 |

房间区域模板（schema v2）：

| `areaId` | 当前模板位置 | 容量 |
|---|---|---:|
| `LEFT_CABINET` | 左侧柜台 | 30 |
| `MAIN_TABLE` | 中央大牌桌 | 30 |
| `RIGHT_TABLE` | 右侧小牌桌 | 30 |

当前所有可搜索房间暂时共用同一模板；后续地图美术可按房间类型替换模板，但服务端区域标识和结算边界保持不变。

房间访问状态：

| 状态 | 含义 |
|---|---|
| `ACTIVE` | 50 秒内，可观察、拾取、丢弃或离开 |
| `LEFT` | 玩家主动离开，访问关闭 |
| `TIMED_OUT` | 服务端时间达到期限，访问自动关闭 |

## 3. HTTP API

基础路径：`/api/search`

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 服务健康和契约版本 |
| `POST` | `/games` | 按对局 ID 初始化 5×5 房间物资和玩家初始背包 |
| `POST` | `/games/:gameId/visits` | 移动结算后创建 50 秒房间访问 |
| `GET` | `/games/:gameId/visits/:visitId?playerId=...` | 拉取服务端时间、曝光、背包和房间快照 |
| `POST` | `/games/:gameId/visits/:visitId/observe` | 携带 `areaId` 打开区域搜索；已曝光未拾取物立即展示，其余物品每 2 秒揭示 1 件 |
| `POST` | `/games/:gameId/visits/:visitId/pickup` | 将当前可见物资事务性移入背包 |
| `POST` | `/games/:gameId/visits/:visitId/drop` | 将背包物品事务性放回当前房间 |
| `POST` | `/games/:gameId/visits/:visitId/finish-observation` | 关闭浮层并返回房间页 |
| `POST` | `/games/:gameId/visits/:visitId/leave` | 关闭房间访问并进入下一移动回合 |

所有修改请求必须携带 `X-Request-Id`。服务端在同一对局中缓存最近 100 个请求结果；相同请求 ID 重放时返回首次结果，不重复修改资产。

## 4. 主要错误码

| 错误码 | HTTP | 客户端处理 |
|---|---:|---|
| `GAME_NOT_FOUND` | 404 | 重新初始化对局或进入本地降级 |
| `VISIT_NOT_FOUND` | 404 | 停止操作并重新同步当前房间 |
| `SEARCH_TIMEOUT` | 409 | 关闭浮层并进入下一移动回合 |
| `VISIT_CLOSED` | 409 | 禁止继续修改，使用最终快照 |
| `ITEM_NOT_VISIBLE` | 400 | 取消拖拽并刷新可见物资 |
| `ITEM_UNAVAILABLE` | 409 | 其他操作已先完成，刷新房间 |
| `ITEM_NOT_OWNED` | 400 | 恢复背包画面并刷新快照 |
| `OBSERVATION_NOT_ACTIVE` | 409 | 取消丢弃并返回当前房间快照 |
| `BACKPACK_FULL` | 400 | 保持物品在房间并显示满包提示 |
| `AREA_NOT_FOUND` | 404 | 取消打开浮层并刷新房间区域模板 |
| `AREA_FULL` | 409 | 取消丢弃并提示当前区域最多容纳 30 件 |
| `VERSION_CONFLICT` | 409 | 服务端自动重试失败后要求客户端刷新 |

## 5. 数据和并发保证

- 普通及出生房间初始化 4 件，中央金库 10 件，撤离点 0 件；每件物品使用对局种子独立随机分配到三个区域，允许区域为 0 件且不做平均分配。
- 物资从 23 张 `LOOT` 卡中等概率、有放回抽取，每件物资拥有独立 `instanceId`。
- 区域搜索每 2 秒揭示 1 件，已揭示物品持续保留在 30 格区域列表中，不再限制同时展示 2 件。
- 曝光记录按玩家保存；物品实体、拾取归属和区域容量由全局权威状态共享。
- 服务端时间是倒计时和曝光判定的唯一依据；客户端本地时间只用于画面插值。
- CloudBase 使用 `heisino_search_games` 集合保存单局聚合文档，并通过服务端事务比较版本后整体替换；服务端会幂等确认集合存在，并兼容旧版 `{ data: game }` 嵌套文档后在下一次写入时迁移为平铺结构。
- 拾取先校验访问有效、物品可见和背包空位，再在同一事务中更新物品归属与背包。
- 丢弃先校验观察层仍打开、物品所有权和区域容量，再在同一事务中更新背包、房间和当前区域。
- schema v1 对局在下一次写请求时按 `gameId + roomNodeId + instanceId` 确定性补齐 `areaId`；旧观察层自动关闭，玩家可重新选择区域。
- 每次成功修改都会递增 `version`；响应版本与已提交文档版本一致，冲突时最多自动重试 4 次。

## 6. CloudBase 部署约束

- Web 云函数使用 `@cloudbase/node-sdk` 访问文档数据库，函数环境变量必须提供 `CLOUDBASE_APIKEY`；代码将其作为 SDK 的 `accessKey`，也兼容成对提供的 `TENCENTCLOUD_SECRETID` / `TENCENTCLOUD_SECRETKEY`。
- `CLOUDBASE_ENV_ID` 可显式指向测试环境，未设置时使用运行时 `SCF_NAMESPACE`；`SEARCH_GAME_COLLECTION` 未设置时默认为 `heisino_search_games`。
- API Key 属于部署密钥，不写入源码、`cloudbaserc.json`、接口响应或日志。
- `cloudbaserc.json` 不得声明 `heisino-game.envVariables`；CLI 会整体覆盖该函数的环境变量，局部声明非敏感配置会造成已注入的 API Key 丢失。
- HTTP 网关 `/api/search` 路由转发到 `heisino-game`；处理器同时兼容本地完整路径和 CloudBase 网关剥离 `/api/search` 前缀后的路径。
- 部署后必须运行 `npm run verify:search:production`，同时验证建局数据、房间数量、4/10/0 物资分布、区域守恒、2 秒持续曝光、拾取/区域丢弃事务和离开状态。

## 7. 降级规则

搜索 API 初始化失败时，客户端使用相同的 4/10/0 数量、三分区随机分配、30 格容量、50 秒期限和 2 秒持续曝光规则运行本地状态机。降级只用于开发测试和短时故障兜底，不作为正式多人资产结算来源。
