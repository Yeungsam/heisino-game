# 搜索回合接口契约

文档版本：2.1.0（独立搜索 HTTP/schema 版本保持 `2.0.0` / `2`）

核对日期：2026-11-22；当前实现基线 `67e27c0`，最新发布记录提交 `403bd45`。

状态：正式账号搜索与独立兼容搜索并存。本文第 2–6 节的 `/api/search` 字段、错误码和事务策略只属于独立兼容服务，不能直接当作账号接口契约。

## 1. 权威边界

正式客户端通过账号服务推进单人/多人对局，搜索、战斗、移动和资产统一在服务端权威状态内执行。客户端可以播放拖拽和搜索水波纹动画，但只有收到服务端成功快照后才能确认拾取或丢弃。断网不会切换为可修改账号资产的本地游戏。

| 路径 | 当前用途 | 身份与资产边界 | 实现 |
|---|---|---|---|
| `/api/account/game`、`/resume`、`/heartbeat` | 当前微信客户端的单人/多人搜索 | Bearer 会话决定玩家身份；库存、搜索、结算统一由账号服务处理 | [账号服务](../functions/heisino-account/service.js)、[多人服务](../functions/heisino-account/multiplayer.js)、[客户端账号 API](../client/js/api/account.js) |
| `/api/search/games/...` | 早期 M2.4 独立搜索兼容与专项验证 | 显式 `gameId` / `playerId` 标识；不承担微信账号库存、多人身份鉴权或永久资产结算 | [独立服务](../functions/heisino-game/search-domain.js)、[处理器](../functions/heisino-game/http-handler.js) |
| 本地 `GameEngine` | 共享规则、画面投影、模拟测试与旧原型 | 不能在账号接口失败时替代服务端写入资产 | [游戏引擎](../client/js/core/game-engine.js) |

### 1.1 正式账号搜索请求

`POST /api/account/game` 请求携带 `Authorization: Bearer <游戏会话>` 和 JSON 请求体：

```json
{
  "gameId": "当前账号的对局 ID",
  "turn": 2,
  "action": "observe",
  "areaId": "MAIN_TABLE",
  "requestId": "沿用到重试的操作 ID"
}
```

| `action` | 附加字段 | 行为 |
|---|---|---|
| `observe` | `areaId` | 打开本玩家有权搜索的区域；普通搜索每 0.5 秒揭示一件，战利品区域立即揭示 |
| `pickup` | `instanceId` | 从当前观察层拾取已可见、可取得的实例；检查十件容量和同类装备限制 |
| `drop` | `instanceId` | 从本人背包丢入当前观察区域，检查观察层有效及区域容量 |
| `finish-observation` | 无 | 关闭观察层，不等同结束整个房间行动 |
| `leave` | 无 | 结束本玩家本轮访问；多人需等待本轮其他玩家完成后共同换轮 |

成功响应使用 `{ ok: true, data }`；`data` 包含 `profile`、`activeGame`、`lastSettlement`、`serverNow`、`revision` 等账号字段。活动对局的搜索在 `activeGame.search` 中，包含 `visit`、`room` 和按实例逐件投影的 `inventory`。普通搜索最多 50 秒，战后拾取最多 20 秒，以 `visit.deadlineAt` 和服务端阶段为准；多人轮空搜索可与战斗并行。移动回放结束后才开始正常搜索计时。

错误使用 `{ ok: false, error }`。账号搜索可返回 `UNAUTHENTICATED`（401）、`STALE_TURN`、`INVALID_PHASE`、`ITEM_NOT_VISIBLE`、`NOT_OBSERVING`、`BACKPACK_FULL` 等；多数规则拒绝由账号服务返回 409，不能沿用下方独立接口中相同错误码的 400 状态。收到过期或阶段错误后通过账号 `resume` 同步，不能另建独立搜索局续写。

账号 `requestId` 位于请求体。当前单人对局缓存最近 200 个动作指纹，相同 ID 和相同内容不重复执行，改内容复用 ID 返回 `REQUEST_ID_REUSED`；多人按其房间服务的请求与事务策略处理。客户端网络重试复用原 ID、输入和账号身份，收到旧 `revision` 不覆盖新状态；账号切换时停止旧请求。不要把独立服务的“最近 100 个结果快照”语义套用到账号服务。

## 2. 独立兼容搜索：状态模型

物品状态：

| 状态 | 含义 |
|---|---|
| `HIDDEN` | 位于房间且尚未向该玩家曝光 |
| `EXPOSED` | 已曝光但仍留在房间 |
| `IN_INVENTORY` | 已进入玩家背包 |
| `DROPPED` | 玩家主动或战败后留在房间 |
| `DESTROYED` | 已销毁，不再参与搜索 |

房间区域模板（schema v2）：

| `areaId` | 当前模板位置 | 容量 |
|---|---|---:|
| `LEFT_CABINET` | 左侧柜台 | 30 |
| `MAIN_TABLE` | 中央大牌桌 | 30 |
| `RIGHT_TABLE` | 右侧小牌桌 | 30 |

当前所有可搜索房间暂时共用同一模板；后续地图美术可按房间类型替换模板，但服务端区域标识和结算边界保持不变。

房间访问状态：

| 状态 | 含义 |
|---|---|
| `ACTIVE` | 50 秒内，可观察、拾取、丢弃或离开 |
| `LEFT` | 玩家主动离开，访问关闭 |
| `TIMED_OUT` | 服务端时间达到期限，访问自动关闭 |

## 3. 独立兼容搜索：HTTP API

基础路径：`/api/search`

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 服务健康和契约版本 |
| `POST` | `/games` | 按对局 ID 初始化 5×5 房间区域数量和玩家初始背包 |
| `POST` | `/games/:gameId/visits` | 首次访问时生成该房间物资，并创建 50 秒房间访问 |
| `GET` | `/games/:gameId/visits/:visitId?playerId=...` | 拉取服务端时间、曝光、背包和房间快照 |
| `POST` | `/games/:gameId/visits/:visitId/observe` | 携带 `areaId` 打开区域搜索；已曝光未拾取物立即展示，其余物品每 0.5 秒揭示 1 件 |
| `POST` | `/games/:gameId/visits/:visitId/pickup` | 将当前可见物资事务性移入背包 |
| `POST` | `/games/:gameId/visits/:visitId/drop` | 将背包物品事务性放回当前房间 |
| `POST` | `/games/:gameId/visits/:visitId/finish-observation` | 关闭浮层并返回房间页 |
| `POST` | `/games/:gameId/visits/:visitId/leave` | 关闭房间访问并进入下一移动回合 |

访问及物品操作应携带 `X-Request-Id`（处理器也接受请求体 `requestId`）。服务端在同一对局中缓存最近 100 个请求结果；相同请求 ID 重放时返回首次结果，不重复修改搜索状态。若旧缓存包含停用卡，迁移后刷新快照，不重放原操作。`POST /games` 按 `gameId` 幂等建局，不依赖该缓存。该兼容接口不负责账号资产鉴权，不用它证明玩家拥有战备卡或发生了真实扣仓。

成功响应：

```json

  "ok": true,
  "data": {
    "gameId": "game-123",

      "status": "ACTIVE",
      "startedAt": 1000,

    },
    "room": {
      "nodeId": "n_0_0",
      "unpickedCount": 4,
      "unsearchedCount": 2,
      "canObserve": true,
      "activeAreaId": "MAIN_TABLE",
      "areas": [
        { "areaId": "LEFT_CABINET", "itemCount": 1, "unsearchedCount": 1 },
```

## 4. 主要错误码

| 错误码 | HTTP | 客户端处理 |
|---|---:|---|
| `GAME_NOT_FOUND` | 404 | 仅在独立测试流程重新初始化；账号对局应调用账号恢复接口 |
| `VISIT_NOT_FOUND` | 404 | 停止操作并重新同步当前房间 |
| `SEARCH_TIMEOUT` | 409 | 关闭浮层并进入下一移动回合 |
| `VISIT_CLOSED` | 409 | 禁止继续修改，使用最终快照 |
| `ITEM_NOT_VISIBLE` | 400 | 取消拖拽并刷新可见物资 |
| `ITEM_UNAVAILABLE` | 409 | 其他操作已先完成，刷新房间 |
| `ITEM_NOT_OWNED` | 400 | 恢复背包画面并刷新快照 |
| `OBSERVATION_NOT_ACTIVE` | 409 | 取消丢弃并返回当前房间快照 |
| `BACKPACK_FULL` | 400 | 保持物品在房间并显示满包提示 |
| `AREA_NOT_FOUND` | 404 | 取消打开浮层并刷新房间区域模板 |
| `AREA_FULL` | 409 | 取消丢弃并提示当前区域最多容纳 30 件 |
| `VERSION_CONFLICT` | 409 | 服务端自动重试失败后要求客户端刷新 |

## 5. 独立兼容搜索：数据和并发保证

- 新局普通房间生成 0、1、2、3、4 件的概率依次为 20%、20%、30%、20%、10%；中央金库生成 6、7、8、9、10 件的概率依次为 40%、10%、10%、10%、30%。出生点和撤离点为 0 件初始物资。物品独立分配到三个区域，区域允许为 0 件。
- 同类型房间使用同一套飞书权重。每次按权重有放回抽取，重复卡牌拥有不同 `instanceId`。未访问时只返回区域数量；访问后持久化物品，重进不补货。上线前已创建的对局继续使用已存物资。
- 区域搜索每 0.5 秒揭示 1 件，已揭示物品持续保留在 30 格区域列表中，不再限制同时展示 2 件。
- 曝光记录按玩家保存；物品实体、拾取归属和区域容量由全局权威状态共享。
- 服务端时间是倒计时和曝光判定的唯一依据；客户端本地时间只用于画面插值。
- CloudBase 使用 `heisino_search_games` 集合保存单局聚合文档，并通过服务端事务比较版本后整体替换；服务端会幂等确认集合存在，并兼容旧版 `{ data: game }` 嵌套文档后在下一次写入时迁移为平铺结构。
- 拾取先校验访问有效、物品可见和背包空位，再在同一事务中更新物品归属与背包。
- 对局背包按实例计数，每格一件，最多拾取至 10 件。同款占用不同格子。旧存档中的超额物品保留，减少到 10 件以下后可再次拾取。
- 丢弃先校验观察层仍打开、物品所有权和区域容量，再在同一事务中更新背包、房间和当前区域。
- schema v1 对局在下一次写请求时按 `gameId + roomNodeId + instanceId` 确定性补齐 `areaId`；旧观察层自动关闭，玩家可重新选择区域。
- 每次成功修改都会递增 `version`；响应版本与已提交文档版本一致，冲突时最多尝试 4 次事务写入。

## 6. CloudBase 部署约束

- Web 云函数使用 `@cloudbase/node-sdk` 访问文档数据库，函数环境变量必须提供 `CLOUDBASE_APIKEY`；代码将其作为 SDK 的 `accessKey`，也兼容成对提供的 `TENCENTCLOUD_SECRETID` / `TENCENTCLOUD_SECRETKEY`。
- `CLOUDBASE_ENV_ID` 可显式指向测试环境，未设置时使用运行时 `SCF_NAMESPACE`；`SEARCH_GAME_COLLECTION` 未设置时默认为 `heisino_search_games`。
- API Key 属于部署密钥，不写入源码、`cloudbaserc.json`、接口响应或日志。
- `cloudbaserc.json` 不得声明 `heisino-game.envVariables`；CLI 会整体覆盖该函数的环境变量，局部声明非敏感配置会造成已注入的 API Key 丢失。
- HTTP 网关 `/api/search` 路由转发到 `heisino-game`；处理器同时兼容本地完整路径和 CloudBase 网关剥离 `/api/search` 前缀后的路径。
- 部署后运行 `npm run verify:search:production`，用固定种子验证普通房间 3 件、空普通房间 0 件、金库 7 件、区域守恒、曝光、拾取、离开及重进不补货。

## 7. 失败与恢复边界

- 正式微信账号对局失败时显示错误、保留有限重试并通过账号恢复接口同步；不足 10 分钟可恢复原局，满 10 分钟按服务端规则判负。不允许把失败请求改发 `/api/search` 或本地引擎后返仓。
- 独立服务的 `SEARCH_TIMEOUT` / `VISIT_CLOSED` 只表示该独立访问已结束，不能直接推动账号对局或永久资产结算。
- 本地引擎与独立接口保留兼容测试。旧文档的“4/10/0 固定数量、2 秒揭示、故障时本地续玩”是历史 M2.4 原型说明，不是当前正式客户端的容错规则。当前新局使用随机数量和 0.5 秒揭示，旧存档按兼容逻辑恢复。
- 卡库结构可以回退随包目录，缺图有视觉备用方案；这些展示降级不扩大账号或搜索写权限。

## 8. 核对与后续待定

接口和共享规则变更按[CloudBase 发布与验收](CloudBase发布与验收.md)部署受影响的账号/搜索函数；用 Node.js 22 或更高版本执行五轮全量回归。独立搜索运行 `npm run verify:search:production`，账号搜索需另外验证真实账号鉴权、开局、搜索、恢复和结算，不以独立接口或健康检查替代。

技能数值与附加效果、未来房间专属区域模板等尚未完整实现的设计保持待定。最新手机、多设备、弱网和前后台交互仍按[全局回归测试用例](全局回归测试用例.md)手动验收。
