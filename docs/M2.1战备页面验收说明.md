# 行动战备页面验收说明（M2.1 沿革与当前基线）

文档版本：1.0.0
最后整理：2026-11-22
当前实现基线：`403bd45`（2026-11-12），本次仅更新文档，不新增功能。

原 M2.1 0.4.0 记录为“34 项自动化测试、生产卡牌服务联调与微信开发者工具卡面视觉验收通过，等待 PMO/产品经理完整交互验收”。这是历史结论，不代表当前版本真机交互已经完成。下列流程和清单已按当前代码更新，新清单不继承旧版验收勾选。

## 1. 目标与入口

玩家从真实账号仓库选择本局携带卡牌，真正开局时才由服务端扣除库存并建立局内物品实例。选择不是展示用的全卡库，也不在进入大厅、等待房间或取消时扣仓。

```text
码头首页“开始游戏”
→ 行动战备：从实际拥有的武器、防具和技能选择0–4张
→ “前往码头”进入大厅
→ 单人模式 / 创建或加入多人房间
→ 单人实际开局 / 多人房主实际开局
→ 服务端事务扣仓，建立与所选一致的独立物品实例
```

当前多人支持 2–3 名真人，由房主开局；正式单人是 `SINGLE`，不补两名随机移动机器人。旧版模拟匹配和 `SINGLE_TEST` 只保留兼容。完整规则见[游戏产品流程图](游戏产品流程图.md)。

## 2. 页面与卡牌

- 左侧为白鸽接应员 NPC 和准备引导。
- 中间标题为“仓库”，只显示玩家实际拥有且尚可选择的武器、防具、技能，物资卡不展示；独立首页仓库仍称“玩家仓库”。
- 仓库按真实卡面比例纵向滚动，不用固定“拥有所有卡”的数量断言。当前全目录为 51 张（7 武器、13 防具、8 技能、23 物资），其中战备候选共 28 种，但每位玩家仅显示其实际拥有部分。
- 右侧固定显示十格；最多带入四张，剩余为空格，不表示可多带。局内每件独立占格，仓库同卡每格最多 99 张，堆叠不增加四张总上限。
- 底部为“返回首页”和“前往码头”。结算页“再来一局”重新进入战备。
- 卡面按需加载远端资源，失图时保留可识别、可操作的占位；不能因卡图失败伪造或改变拥有数量。

## 3. 当前交互及权威约束

| 操作/约束 | 当前预期 |
|---|---|
| 轻点仓库/背包卡 | 显示居中卡面大图与黑色蒙层，无底部说明；再轻点任意位置关闭，点击不传下层 |
| 放入/放回 | 关闭大图后点“放入背包”/“放回仓库”，或拖动到对应区域 |
| 滚动与拖动 | 纵向滚动仓库；横向拖卡时卡面跟随手势。长按、取消、滚动不能误开预览或投放 |
| 数量 | 同款技能可带多张，但不能超过实际拥有数量；每次转移一张 |
| 总上限 | 四张；第五张拒绝并提示 |
| 装备上限 | 当前互动战斗新局最多一张武器、一张防具；同类第二张拒绝，服务端同步校验 |
| 类型 | 客户端不展示物资卡，伪造请求也不能带入物资、未知或退役卡 |
| 空手 | 可出发；未带武器或防具的一侧互动战斗倍率为 40% |
| 返回首页 | 当前会话内保留尚未开局的选择，不提前写扣仓流水 |
| 进入/离开大厅房间 | 等待、退出不扣仓；房主退出转交下一成员，空房关闭 |
| 真正开局 | 服务端重验数量、类型、装备限制及版本，事务扣仓一次；请求重试沿用原 requestId |
| 新版多人版本校验 | 全员战斗版本合格才能开局，缺少标记返回对应昵称并保留房间与资产 |
| 初始化 | 所选物品成为本局独立实例，装备占格且参与攻防；武器、防具无耐久 |
| 技能 | 可携带和在战斗消耗，但当前没有数值效果，不能按卡面文字验收效果 |
| 账号/网络异常 | 不允许本地降级扣仓；身份切换终止旧操作的跨账号重试，恢复真实云端库存 |

## 4. 最新版真机验收清单

以下未勾选项表示仍需按最新版开发预览实际验收，不据历史截图推定通过。

- [ ] 安卓和 iOS 横屏显示 NPC、仓库、十格背包及底部按钮，微信胶囊不遮挡关键操作。
- [ ] 初始新账号仅有礼包武器、防具、技能各一张，已有账号仅展示真实战斗卡库存，不默认拥有全部目录。
- [ ] 仓库纵向滑动，轻点大图可关闭；长按、滑动、触控取消及拖拽不会误开预览或串到下层操作。
- [ ] 按钮及手势均可逐张放入/取下；卡面跟手，库存剩余数量与选择一致。
- [ ] 第五张、第二张武器、第二张防具及超拥有数量的选择均拒绝；空手可进入大厅。
- [ ] 返回首页再进仍保留本会话选择；仓库云端数量和流水尚未扣除。
- [ ] “前往码头”进入真实大厅，可返回战备；创建、加入及退出等待房均不扣仓。
- [ ] 使用至少两台新版客户端开局，实际扣仓各一次；版本过低成员被点名，失败开局不扣仓。
- [ ] 单人开局的带入物与选择一致；开局回包丢失后恢复同局，不重复扣仓。
- [ ] 真机弱网及首次卡面加载时仍可浏览、预览和转移，不因缺图增加卡牌或错误出发。
- [ ] 实际对局中武器、防具占背包槽并参与攻防；技能消耗没有当前未实现的附加数值。
- [ ] 撤离后原物返仓一次，失败只损失本局物品；“再来一局”回到战备并读取更新库存。
- [ ] 切换微信账号后不显示上一账号战备和仓库，也不把旧请求重试到新账号。

## 5. 自动化与线上验证入口

- [战备模型](../tests/loadout.test.js)：实际数量、类型过滤、四张上限、同类装备限制、转入与取回。
- [卡牌预览与战备触控](../tests/card-preview-ui.test.js)、[卡牌滚动](../tests/card-scroll-ui.test.js)：按钮/拖动、长按/滚动/取消、大图与格子。
- [账号服务](../tests/account-service.test.js)、[互动战斗](../tests/combat-round.test.js)：服务端战备校验、真实扣仓、幂等及装备参与结算。
- [单人界面](../tests/single-player-ui.test.js)、[多人界面](../tests/multiplayer-ui.test.js)、[身份切换](../tests/global-account-ui.test.js)：真实生产 Canvas 和触控处理配合模拟身份，覆盖大厅、开局恢复及账号隔离。
- [全局回归矩阵](全局回归测试用例.md)与[自动化索引](自动化用例索引.md)维护当前全量用例，历史“34 项”“52 张 JPEG”等数字不再用于当前验收。

Node.js 22 或以上执行：

```bash
npm run test:regression
npm run test:regression -- --rounds 5
```

功能改动时运行 `npm run test:regression -- --update-cases`，同步提交实现、测试、矩阵与索引。线上变更必须按[CloudBase 发布与验收](CloudBase发布与验收.md)部署受影响函数并检查真实公网业务；本地回归、开发工具画面或健康检查不替代公网事务与真机验收。

- 技能实际效果与独立技能预判阶段待定，不因卡牌可携带或可消耗视为已实现。
