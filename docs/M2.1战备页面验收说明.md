# M2.1 战备页面验收说明

版本：0.3.0
状态：自动化测试与微信开发者工具编译通过，等待 PMO/产品经理真人验收

## 1. 目标

在玩家点击主页“开始游戏”后增加行动战备环节。玩家先从仓库选择本局携带卡牌，再进入原有匹配流程；选择结果必须成为对局内真实初始背包，而不是仅用于页面展示。

```text
开始游戏
→ 行动战备
→ 从仓库选择最多4张卡牌
→ 开始匹配
→ 匹配成功
→ 所选卡牌写入本局初始背包
```

## 2. 页面结构

- 左侧：白鸽接应员 NPC 与行动准备引导。
- 中间：玩家仓库，当前测试版本默认拥有卡牌配置中的全部卡牌。
- 右侧：固定 10 格行动背包；前 4 个为当前版本可用携带位。
- 底部左侧：返回首页。
- 底部右侧：开始匹配。

## 3. 交互规则

- 仓库卡牌第一次点击为选中并展示卡牌摘要，再次点击同一张卡牌放入背包。
- 可直接将仓库卡牌拖拽到右侧背包。
- 背包卡牌第一次点击为选中，再次点击放回仓库。
- 可将背包卡牌拖回中间仓库。
- 当前版本最多携带 4 张卡牌，第 5 张会被阻止并显示提示。
- 行动背包固定显示 10 格，未开放的剩余格仍显示为空格。
- 允许空手进入匹配，但页面会提示推荐至少携带 1 张武器卡。
- 进入对局后，所选卡牌全部成为玩家初始背包物品；第一张武器卡自动装备。
- 点击结算页“再来一局”返回战备页面，以便重新配置下一次行动。

## 4. 真人验收清单

- [ ] 主页点击“开始游戏”后进入战备页，而不是直接进入匹配。
- [ ] NPC、引导文案、仓库、背包和底部按钮均完整显示。
- [ ] 仓库中显示当前版本全部 10 张卡牌。
- [ ] 第一次点击仓库卡牌显示摘要，再次点击后进入背包。
- [ ] 仓库卡牌可以拖拽到背包。
- [ ] 背包卡牌可以双击式放回仓库，也可以拖回仓库。
- [ ] 最多只能放入 4 张卡牌，第 5 张被阻止并出现提示。
- [ ] 背包始终显示 10 个格子。
- [ ] 点击“返回首页”回到主页，已选择战备在本次会话内保留。
- [ ] 点击“开始匹配”进入原有匹配流程，并显示本次战备数量。
- [ ] 进入对局后，右侧背包与战备选择一致。
- [ ] 若携带武器，第一张武器自动进入装备状态。
- [ ] 结算后点击“再来一局”回到战备页。

## 5. 自动化覆盖

- 仓库默认拥有全部卡牌。
- 行动携带上限为 4 张。
- 背包固定为 10 格。
- 放入背包后从仓库移除，取下后返回仓库。
- 战备卡牌写入对局初始背包。
- 第一张武器自动装备。

执行：

```bash
npm run check
```

## 6. 当前边界

- 当前卡牌配置主要为武器与物资；防具、技能卡加入配置后会自动出现在仓库，但其正式装备槽和技能生效逻辑仍需后续实现。
- 当前默认每张卡牌拥有 1 份，不支持同卡多份数量堆叠。
- 战备选择只在本次小游戏会话内保留，尚未接入账号仓库和云端持久化。
