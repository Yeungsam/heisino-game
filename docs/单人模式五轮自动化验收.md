# 单人模式五轮自动化验收

基线 `879cb71`，分支 `codex/multiplayer-single-player`。复用多人验收的回环 HTTP、模拟微信身份、可控时钟、生产 Canvas 和触控测试。每轮独立执行并记录实测结果。

## 第 1 轮 · 开局、扣仓与丢包恢复

- 从战备和码头进入正式单人，核查独立账号、开局请求重试、单次扣仓和地图上的单玩家状态。
- 首跑时，开局已提交但回包和立即恢复请求都丢失。网络恢复后大厅仍停留，玩家无法自动进入原对局。
- 已修复。大厅收到已有对局状态后自动请求恢复。复测 4/4 通过，原对局和扣仓流水均只有一份。

## 第 2 轮 · 守卫判定与战斗界面

- 用服务端可控随机数验证 30% 两侧、出生点跳过、未触发房间也只判定一次、金库第六回合开放，以及守卫自动战败和两件蓝色装备。
- 首跑时，战斗结果页的「查看战利品」在房间超时后还能进入旧房间。
- 已修复。有效房间期限内才允许继续，已过期的界面显示同步状态。复测 3/3 通过。

## 第 3 轮 · 搜索、拖拽与计时

- 验证未曝光物资不可拾取、2 秒曝光边界、拖入背包、丢回原区域、堆叠和回合结束后物资状态。
- 首跑时，计时归零后松开旧拖拽仍会发送拾取，搜索按钮也未随期限锁定。
- 已修复。房间和搜索动作共用服务端期限，锁定旧热区并拦截旧拖拽。复测 5/5 通过。

## 第 4 轮 · 冷启动与断线恢复

- 冷启动恢复同一局、同一搜索区域、已曝光物资和剩余时间，检查 9 分 59.999 秒仍可恢复及满十分钟个人失败。
- 首跑时，玩家完成搜索回到房间后冷重启，仍被带回此前已看过的战斗结果页。
- 已修复。若服务端已有完成的搜索记录，重启直接回到对应房间。复测 4/4 通过。

## 第 5 轮 · 撤离、资产与放弃

- 通过触控拾取带蓝标的守卫圆盾，走到撤离点并核对重复结算、金币和再次带入。另测试取消放弃及弹窗跨回合。
- 首跑时，放弃弹窗确认与服务端自动换轮撞在一起，整局退出被错误当作旧回合操作拒绝。
- 已修复。放弃按对局 ID 处理，换轮后仍可确认本局，旧弹窗无法操作新对局。复测 4/4 通过。

## 汇总

- 五轮均按首跑、记录、修复、复测的顺序完成。
- `npm run check` 通过 150/150，包含原有多人回归。五个单人界面场景连续执行十遍，共通过 50 次。
- 在本机 Chrome 抽查 667×375 和 812×375 两种实际 Canvas 尺寸，核对单人入口、守卫胜利、房间、搜索计时和守卫圆盾蓝标。
- 本次使用本地模拟账号和内存仓库，CloudBase 与微信真机待部署后验收。

`node --test --test-name-pattern '单人第1轮' tests/single-player-ui.test.js` 可单独运行第 1 轮。更换匹配名即可运行其他轮次。
