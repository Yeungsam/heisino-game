# M2 完整流程测试包说明

版本：0.2.0
状态：基础流程已验收，由 M2.1 战备页面迭代承接

## 1. 本阶段目标

M2 将 M1 的规则原型扩展为可从开始页一直玩到终局结算的本地纵切版本。它用于验证游戏流程、页面层级、操作可读性和核心规则衔接，不代表正式联网架构或最终美术交付质量。

完整流程：

```text
资源加载
→ 开始游戏
→ 匹配等待 / 单人测试立即开始
→ 匹配成功倒计时
→ 回合开始与移动选择
→ 同时公布移动结果
→ 搜索 / 战斗
→ 回合结果
→ 下一回合
→ 呼叫撤离并等待一回合 / 战败 / 12回合超时
→ 结算
```

## 2. 画面与交互

- 开始页：使用红金赌场主视觉，保留“开始游戏”为主入口。
- 匹配页：以赌场海岛为背景，显示三个席位、5 分钟剩余时间、取消匹配和单人测试按钮。
- 移动回合：顶部显示回合、HP、警报状态和资产；左侧 5×5 节点地图；右侧显示装备与背包；底部确认移动。
- 搜索回合：点击物品第一次翻开信息，第二次拾取；背包物品可拖至右下角丢弃。
- 战斗回合：显示双方角色、HP、骰子轮次和结果；M2 暂由规则引擎自动完成三轮战斗。
- 回合结果：显示本轮日志，可进入下一回合；位于唯一撤离点时可以呼叫接应。
- 结算页：区分撤离成功与失败，显示原因、回合、剩余 HP、物品数和战利品价值。
- 声音：本版本保持静音。

## 4. 真人验收清单

### A. 开始与匹配

- [ ] 横屏加载页完成后进入红金赌场开始页，画面无拉伸和明显裁切错误。
- [ ] 点击“开始游戏”进入匹配页。
- [ ] 匹配页显示 5 分钟倒计时、三个席位和取消按钮。
- [ ] 等待时两名模拟玩家依次加入，随后出现匹配成功倒计时。
- [ ] 重新进入匹配后点击“单人测试·立即开始”，可以直接开始对局。
- [ ] 点击取消匹配返回开始页；本地玩家退出后空房被销毁。

### B. 移动回合

- [ ] 只能选择原节点或上下左右相邻节点，不能斜向移动。
- [ ] 第 1–5 回合无法选择中央金库，第 6 回合开始开放。
- [ ] 选择期间无法看到其他玩家目的地，确认后统一显示移动轨迹。
- [ ] 不操作直到移动倒计时结束时，玩家停留原节点。

### C. 搜索、背包与战斗

- [ ] 单人进入节点后进入搜索画面。
- [ ] 物资第一次点击显示名称/价值，第二次点击进入背包。
- [ ] 背包物品可拖到右下角丢弃，丢弃物仍留在当前节点。
- [ ] 两名玩家同节点时进入战斗画面并显示结算结果。
- [ ] 三名玩家同节点时随机两人战斗，另一人搜索，物资只被分配一次。
- [ ] 战斗完成后武器耐久减少；归零时装备销毁。

### D. 警报、撤离与结算

- [ ] 第 10、11、12 回合开始时，存活玩家先扣除 10 HP。
- [ ] 警报伤害使 HP 归零时立即进入失败结算。
- [ ] 到达右下角唯一撤离点后可以呼叫接应。
- [ ] 呼叫后经过一个完整回合，且未被警报击败时进入成功结算。
- [ ] 第 12 回合结束仍未撤离时进入超时失败结算。
- [ ] 结算页显示结果原因、回合、HP、物品数量和价值，并能返回主页或再来一局。

## 5. 已自动化覆盖

- 匹配满员、取消、5 分钟超时销毁和单人测试补位。
- 相邻移动、超时停留、中央金库第 6 回合开放。
- 两段式拾取、满包拒绝、丢弃物保留和三人分流。
- 战斗回合上限、武器耐久、HP 归零战败。
- 第 10 回合警报伤害及其先于撤离完成的结算顺序。
- 撤离消耗一回合、第 12 回合超时失败。

执行：

```bash
npm run check
```

## 6. 待 PMO 确认的边界

1. 第 12 回合到达撤离点后才呼叫接应，当前判定来不及完成并失败；是否确认。
2. 其他两名玩家都战败后，最后一名存活者当前进入提前结束结算；是否应自动判定撤离成功，还是仍需走到撤离点。
3. 正式回合 55 秒中，移动选择固定 15 秒、其余时间用于搜索/结果展示的分配是否确认。
4. 完全平局时当前双方均不淘汰，是否确认。

上述边界不会阻碍本地流程验收，但进入权威服务端开发前必须冻结。
