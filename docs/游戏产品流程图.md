## 3. 启动、账号与主页

- 冷启动通过 `wx.login` 重新确认当前微信身份，不能直接沿用上一个微信用户的缓存仓库。身份变化时停止旧操作的跨账号重试。
- 首次资料可使用默认头像与自填昵称。昵称为 2–16 个汉字、英文字母、数字或下划线，经 NFKC 规范化、格式校验及微信内容审核；审核失败不能绕过。
- 首次建号仅发放一次 `wp_006`、`ar_001`、`sk_001` 各 1 张，金币为 0。礼包、扣仓、交易、返仓以服务端事务与资产流水为准。
- 首页为夜间离岸码头，保留商店、仓库、开始游戏三个入口。按 Figma 分层设计与横屏安全区等比布局；背景铺满，前景元素不得被微信胶囊遮挡。
- 当前有效卡库 51 张：武器 7、防具 13、物资 23、技能 8，使用 50 张新版 JPEG；守卫圆盾复用赌场圆盾卡面。退役卡 `sk_002`、`sk_003`、`loot_008` 不展示、不入局，旧资产访问时清理并保留历史流水。
- 卡库失败可回退内置目录，卡面按需加载；账号接口失败保留错误和重试，不本地补写资产。
- 全局保持静音。500ms 轻点击反馈只表示收到触控，不表示服务端操作成功。

仓库按服务端持有数量显示，默认“全部”筛选；同卡每格最多 99 张，100 张显示 99+1。总资产为金币加所有库存卡牌售价，切换分类不改变总资产。轻点卡牌打开居中大图与黑色蒙层，无底部效果说明；再点任意位置关闭，长按、滚动及拖拽不会误开预览。

商店货架出售 A/B 级武器、防具、技能共 16 种，买价为售价的 120%；玩家可出售四类持有卡牌，包括 S/SS 和守卫圆盾（圆盾售 1 金币且不能买入）。左栏逐张加入订单，右栏每格一张，可移回；待售剩余数量归零时隐藏。确认后整单事务成交，余额、库存、报价或阶段不合法时整单不变。同单超时沿用原请求号，支持冷启动后确认原订单。已加入房间或有未完成对局时不能交易。

## 5. 码头大厅、单人和多人房间

```mermaid
flowchart TD
    A["进入码头大厅"] --> B{"选择"}
    B -- "单人模式" --> S["SINGLE：仅本人出发，房间可能遭遇守卫"]
    B -- "创建房间" --> C["房主建立 WAITING 房，10分钟期限"]
    B -- "加入房间" --> D["服务端校验空位、状态及战备"] --> C
    C --> E{"房主是否开局"}
    E -- "至少2人、最多3人，全员战斗版本合格" --> F["事务扣仓，房间进入 PLAYING"]
    E -- "版本不合格" --> V["提示对应昵称，保留房间与资产"] --> C
    C -- "成员退出" --> G["不扣仓，房主离开时转交下一位"]
    G -- "还有成员" --> C
    G -- "空房" --> X["CLOSED"]
    C -- "创建后10分钟到期" --> X
```

- 大厅列出待开始房间，可展开游戏中房间，支持分页；已开始的房间不能加入。容量以服务端查询为准，不能依赖陈旧列表判定满房。
- 2–3 人均由房主主动开局，不自动补机器人，不要求固定 3 人。开局核对全员 `combatVersion`；不符时返回 `409 PLAYER_VERSION_TOO_LOW` 和昵称，等待房保留且不扣仓。
- 房间期限为创建后 10 分钟（`multiplayer.js` 的 `WAIT_MS`）；满员、房主转让不重置该期限。
- 正式单人模式为 `SINGLE`，只有本人在地图行动，守卫仅在遭遇时生成。`STANDARD`、`SINGLE_TEST`、5 分钟本地模拟匹配仍作旧协议/测试兼容，不是当前客户端主入口。
- 当前使用 HTTP 请求、心跳和房间快照同步；没有实施 WebSocket 推送或自动排位匹配。

| 项目 | 当前规则 |
|---|---|
| 地图 | 5×5 节点；房间图块不叠加房名，图例、选点目标与进房标题显示房名 |
| 出生点 | 单人 `(0,0)`；多人依成员顺序分配 `(0,0)`、`(0,4)`、`(4,0)` |
| 初始生命 | 每名真人 30 HP，守卫也满血开始 |
| 中央金库 | `(2,2)`，第 1–5 回合锁定，第 6 回合开放 |
| 唯一撤离点 | `(4,4)` |
| 背包 | 局内每张卡按独立实例占一格，容量 10；武器、防具占格，同款不堆叠 |
| 房间库存 | 首次实际访问时按房型数量和权重生成，未访问房间不预生成完整物品 |

地图当前房间采用最亮绿色，可移动房间次级绿色，已选目标强化描边；其他房间 50% 黑色蒙层。红金图针在原位置渐隐、目标位置渐现；金库叠加宝箱，撤离点叠加出口。地图遮罩不得遮挡 HUD。左上角背包入口只读查看，关闭后才恢复地图触控；跨阶段旧手势不能触发下层操作。

## 7. 回合状态机

```mermaid
stateDiagram-v2

    回合开始 --> 毒圈结算: 回合数大于等于12
    回合开始 --> 移动选择: 回合数小于12
    毒圈结算 --> 失败结算: HP归零
    毒圈结算 --> 移动选择: 仍存活
    移动选择 --> 移动结算: 全员提交或15秒到期
    移动结算 --> 轨迹回放: 新版多人房
    移动结算 --> 房间行动: 单人
    轨迹回放 --> 房间行动: 共同播放窗口结束
    房间行动 --> 普通搜索: 获得搜索权
    房间行动 --> 互动战斗: 真人或守卫遭遇
    互动战斗 --> 战利品: 存活且获得可搜索物资
    互动战斗 --> 等待本轮完成: 无搜索物资

    等待本轮完成 --> 自动撤离: 存活且位于撤离点
    等待本轮完成 --> 下一回合: 存活且位于其他节点
    下一回合 --> 回合开始
    失败结算 --> [*]
    自动撤离 --> [*]
```

三人同房的轮空搜索与战斗可并行，不同房间的守卫战与搜索也可并行；全体存活玩家完成本轮行动后才换轮。整回合没有固定 55 秒总上限，也不在第 12 回合强制结束。

## 8. 移动选择与轨迹回放

- 仅可停留或走上下左右相邻节点；禁止斜向、跨格、越界和提前进入锁定金库。
- 服务端最多收集 15 秒隐藏选择；全员提交可提前结算，超时未提交者原地停留。截止后首次提交拒绝，截止前已成功的请求可用原请求号重试。
- 选择阶段不公开对手位置、目的地与节点人数；结算后才公布本回合轨迹。
- 新版多人房间按同一服务端窗口播放：结算后预留 600ms 同步，回放 1.2 秒，结束后开放房间，普通搜索从 50 秒开始。较晚恢复仅播放剩余窗口。旧混合版本房间沿用即时进房兼容。
- 移动请求不被慢心跳占住交互锁，迟到回包不能回滚新位置；场景切换取消旧触摸。

## 9. 地图节点与守卫

| 节点 | 固定房间库存 | 当前遭遇规则 |
|---|---|---|
| 三个出生点 | 0 件 | 可有真人遭遇及玩家丢弃/掉落物，不生成守卫 |
| 普通房间 | 首访随机 0–4 件 | 独自进入可搜索或遭遇守卫；多人同房按人数分流 |
| 中央金库 | 首访随机 6–10 件 | 第 6 回合开放后采用普通遭遇逻辑 |
| 撤离点 | 0 件 | 不生成守卫；先处理当轮真人战斗、搜索及战利品，再自动撤离 |

单人新局每个大回合在合格房间判定 30% 守卫概率，原地停留也会进入该判定；多人仅在独自移动到普通房间/已开放金库时判定 30%，原地停留、真人同房及三人轮空搜索不判定。守卫不占真人名额，沿用满血、两骰一攻一防与蓝装规则。旧局保留历史守卫判定兼容。

## 11. 搜索、拾取与背包

| 项目 | 当前实现 |
|---|---|
| 数量分布 | 普通房间 0/1/2/3/4 件概率为 20%/20%/30%/20%/10%；金库 6/7/8/9/10 件概率为 40%/10%/10%/10%/30% |
| 卡牌抽取 | 按房型权重表有放回抽取；数量和卡牌权重使用独立随机流，缺省卡牌权重为 1 |
| 首访与重进 | 首访生成后不补货，抽到空房也不补；拾取、丢弃及重连保留现状，玩家/守卫掉落另计 |
| 区域 | 左柜台、中央牌桌、右牌桌，允许空区域；底图按五种房型读取本地分包，出生/撤离或缺图沿用可操作的备用场景 |
| 揭示 | 普通搜索进入区域后每 0.5 秒揭示一件并保留；未揭示使用本地卡背；战后 LOOT 区域立即揭示 |
| 区域容量 | 每区域最多 30 件，首屏 10 格，超出可纵向滚动 |
| 时限 | 普通房间页与搜索浮层共用独立 50 秒服务端期限；战后战利品为 20 秒 |
| 拾取 | 将右侧已揭示卡拖入背包，事务成功才写入权威状态；每件独立占格 |
| 满包与装备限制 | 十格满时拒绝拾取且保留原物；当前新局最多 1 武器、1 防具，须先丢旧同类装备才能拾取另一件 |
| 丢弃 | 拖回当前区域后按实例丢弃，物品留在原房间；不按整类或整堆清空 |
| 完成与离开 | “完成搜索”返回房间页；离开房间或到期标记个人行动完成，多人等待其他人，单人推进下一轮 |
| 幂等与恢复 | 请求号防重复入包，迟到/跨回合拖拽不提交；账号资产不允许本地降级写入 |
| 估值 | 背包总值含已装备物各一次；差值=当前持有卡售价总和−开局带入价值；拾取、丢弃、技能消耗、没收和恢复均取服务端快照 |

## 12. 当前互动战斗

```mermaid
flowchart TD
    A["真人或守卫遭遇"] --> B["小回合操作窗15秒"]
    B --> C["真人主动掷3D6，拖到攻/防/托盘，技能可消耗"]
    C --> D{"双方均准备或15秒截止"}
    D -- "否" --> C
    D -- "是" --> E["按已摆骰计算攻防，碰撞2秒"]
    E --> F{"有人归零或已完成3小回合"}
    F -- "否" --> B
    F -- "是" --> G["终局结果展示2秒，按HP再按伤害判胜"]
    G --> H["分配房间物资和最高价两件，阵亡其余物品销毁"]
    H --> I["有可搜索物资者进入20秒战利品，否则等待本轮完成"]
```

- 每场最多 3 个小回合，每轮统一 15 秒操作窗；当前没有独立的 5 秒技能预判阶段。
- 真人每轮只能主动掷骰一次，每颗骰子可放攻击、防御或托盘；0–3 颗均可参与攻防。未掷骰不自动补掷，托盘骰不计分。
- 未掷骰或仅摆部分骰子也可准备；对手未准备时可取消并保留摆放。双方准备立即结算；未准备但到期仍按已摆攻防区的骰子计分。
- 摆放本地即时反馈、后台同步；版本号及请求号防止乱序覆盖和重复操作。准备时提交最新完整布局；已进入结算不能取消。
- 攻/防值分别为相应骰子点数和乘装备百分比后向下取整；未带武器/防具的一侧为 40%。守卫每轮自动两颗骰子随机一攻一防，缩放后大于 0 且小于 1 的值计 1。
- 双方伤害同时计算，每方实际扣血为 `min(自身HP, max(0, 对方攻击−自身防御))`。碰撞阶段 2 秒，只显示实际攻防；终局再展示结果 2 秒。
- 胜负先比较剩余 HP，再比较累计造成伤害。完全相同为平局；双方同时归零时不发战利品。存活败者仍可继续对局，不因输一场直接淘汰。
- 有胜者时，真人胜者获得本战斗线房间物资及败者售价最高的两件（不足两件取实际数量，同价按背包顺序）。阵亡/弃权者其余物品销毁。守卫获胜则没收并销毁玩家最高价两件，玩家若仍存活保留其余物品继续；击败守卫可拾其蓝装。
- 真人平局且存活时房间物资随机均分，奇数余件随机归一方；三人轮空线原分配不变。只有实际获得可搜索物资且仍存活者开放 20 秒战利品，内容立即揭示，可提前完成。
- 技能每个小回合最多消耗一张，重复请求只消耗一次；**当前没有数值效果**。卡面技能描述不等于功能已执行，效果系统待定。
- 武器、防具无耐久，不因战斗次数消耗；警报圈只在大回合开场处理。多人参战者断线满十分钟停止参战，不能继续攻击在线玩家。

## 13. 毒圈、撤离、失败与恢复

| 项目 | 当前规则 |
|---|---|
| 毒圈 | 第 12 回合起，每轮开场存活玩家扣 5 HP；第 10/11 轮不扣，同轮心跳不重复扣 |
| 回合上限 | 不在第 12 回合强制终局，仍存活者继续移动、搜索或撤离 |
| 自动撤离 | 当轮全部行动完成时，存活且位于 `(4,4)` 的玩家自动 `EXTRACTED`；无需呼叫接应和再等一轮 |
| 撤离点遇敌 | 先战斗及完整战利品窗口；阵亡者失败，存活者当轮末撤离 |
| 成功资产 | 当前背包物品原样返仓并记录流水，价值仅估值，不自动兑换金币 |
| 失败资产 | `DEFEATED`、`ABANDONED`、`DISCONNECTED` 均不返本局物品，未带入的仓库库存保留 |
| 仅剩一人 | 继续前往撤离点，不自动获胜或返仓 |
| 单人恢复 | 不足十分钟恢复同局；没有 `game.combat` 的普通移动/搜索阶段可按服务端中断处理补偿计时；互动战斗及仍保留该战斗对象的同轮战利品按截止推进，恢复不会返回可操作的过期阶段 |
| 多人恢复 | 个别断线不暂停其他玩家；返回服务端当前阶段，满十分钟个人失败且停止参战 |
| 最终落盘 | 断线截止按服务端最后联系时间；请求/恢复触发推进与结算，没有已实现的后台定时清扫任务 |
| 结算确认 | 确认绑定本次 settlementId，旧确认不能吞掉新一局结算；重复结算不能再次返仓 |

毒圈归零由规则引擎将物品掉到当前节点；互动战斗阵亡物品按第 12 节处理，不能统一理解为所有战败均掉落全部物品。结算页显示结果、原因、回合、HP、物品数与价值，可返回码头或重新战备。
