## 1. 文档定位

本文是项目从产品规则到技术实现的流程单一事实源，覆盖玩家从启动游戏到完成结算的全部步骤、节点规则、状态转换和例外处理。

规则状态分为三类：

| 标记 | 含义 | 开发要求 |
|---|---|---|
| `已冻结` | PMO 已明确确认，可作为正式实现依据 | 代码、测试和流程图必须保持一致 |
| `M2 临时` | 为当前本地测试包完成闭环而采用 | 进入正式联机开发前替换或再次确认 |
| `待确认` | 不阻塞当前原型，但存在产品边界 | 不得擅自升级为正式规则 |

规则发生变化时，必须同时更新：

1. 本文对应流程图和规则表。
2. “产品决策台账”，新增决策编号；不得覆盖或删除历史决策。
3. “文档变更日志”，说明修改范围。
4. 对应代码、配置和自动化测试。
5. 若视觉或交互受影响，同步更新验收文档和美术需求。

## 6. 回合状态机

```mermaid
stateDiagram-v2
    [*] --> 回合开始
    回合开始 --> 警报圈结算: 回合数大于等于10
    回合开始 --> 撤离完成检查: 回合数小于10
    警报圈结算 --> 战败结算: HP归零
    警报圈结算 --> 撤离完成检查: 仍存活
    撤离完成检查 --> 成功结算: 上回合已呼叫撤离
    撤离完成检查 --> 移动选择: 仍处于ACTIVE
    移动选择 --> 移动结算: 全员提交或15秒结束
    移动结算 --> 搜索: 单人节点或获得搜索权
    移动结算 --> 战斗: 多人遭遇
    战斗 --> 搜索: 胜者获得房间/掉落物搜索权
    战斗 --> 回合结果: 无可搜索物资
    搜索 --> 回合结果: 主动结束或55秒总时限结束
    回合结果 --> 接应等待: 撤离点呼叫接应
    回合结果 --> 下一回合: 未到第12回合末
    接应等待 --> 下一回合: 未到第12回合末
    下一回合 --> 回合开始
    回合结果 --> 超时结算: 第12回合结束仍未撤离
    接应等待 --> 超时结算: 第12回合才呼叫导致无法完成
    战败结算 --> [*]
    成功结算 --> [*]
    超时结算 --> [*]
```

回合执行顺序不可交换：

1. 清理上一回合临时选择、搜索权限和遭遇数据。
2. 第 10–12 回合先对存活玩家结算警报圈伤害 `-10 HP`。
3. HP 归零或以下的玩家立即战败并掉落全部未销毁物品。
4. 对仍存活玩家检查上一回合发起的撤离，满足条件则完成撤离。
5. 检查本地玩家和整局是否已进入终局。
6. 存活玩家进入移动选择阶段。

> 因警报圈先于撤离完成结算，玩家以 10 HP 在第 9 回合呼叫撤离，会在第 10 回合先被警报击败，不能成功撤离。

## 7. 移动选择与节点判定

```mermaid
flowchart TD
    A["进入移动选择，倒计时15秒"] --> B["向玩家显示原节点和相邻合法节点"]
    B --> C{"目标是否合法"}
    C -- "越界或斜向/跨格" --> D["拒绝提交"] --> B
    C -- "第1至5回合选择中央金库" --> E["返回 NODE_LOCKED"] --> B
    C -- "合法" --> F["隐藏保存该玩家选择"]
    F --> G{"所有存活玩家是否已提交"}
    G -- "否且未超时" --> B
    G -- "否但已超时" --> H["未提交玩家默认停留原节点"]
    G -- "是" --> I["统一锁定选择"]
    H --> I
    I --> J["同时更新位置并公布移动轨迹"]
    J --> K["按目标节点对玩家分组"]
    K --> L["进入节点人数判定"]
```

移动规则：

- 每回合只能停留，或移动到上下左右一个相邻节点。
- 不允许斜向移动、跨越节点或走出 5×5 地图。
- 所有玩家同时选择；提交前看不到其他玩家目的地和节点人数。
- 全员完成选择可提前结算；15 秒结束仍未操作的玩家视为停留。
- 统一结算后才显示三名玩家的移动轨迹。
- 抵达撤离点不会立刻成功；应先完成该节点遭遇，再由存活玩家主动呼叫撤离。

## 11. 战斗流程

```mermaid
flowchart TD
    A["同节点触发玩家战斗"] --> B["读取双方HP、武器倍率和防御倍率"]
    B --> C["战斗小回合 1"]
    C --> D["技能预判 5秒"]
    D --> E["各掷3颗D6并在10秒内分配"]
    E --> F["计算攻击、防御与双方伤害"]
    F --> G["播放结算表现 2秒"]
    G --> H{"是否有人HP归零或已完成3个小回合"}
    H -- "否" --> I["进入下一战斗小回合"] --> D
    H -- "是" --> J["确定胜负"]
    J --> K["双方装备耐久各减少1"]
    K --> L{"耐久是否归零"}
    L -- "是" --> M["装备销毁并移出背包"]
    L -- "否" --> N["保留装备"]
    M --> O["败者掉落物资，胜者获得搜索权"]
    N --> O
    O --> P["进入搜索或回合结果"]
```

正式目标规则：

- 每场战斗最多 3 个小回合。
- 每个小回合为：技能预判 5 秒 → 3D6 分配 10 秒 → 攻防结算与动画 2 秒。
- 三颗骰子可自由分配到攻击区和防御区。
- 攻击值为攻击骰点数和乘以卡牌攻击倍率；防御值按防御骰和防御倍率计算。
- 单次伤害不低于 0，并从目标当前 HP 扣除。
- 有玩家 HP 归零时立即结束战斗。
- 三轮后优先比较累计造成伤害；相同则比较剩余生命值。
- 武器和防具最大耐久统一为 2；完成一场战斗消耗 1 点耐久。
- 战斗进行期间不结算警报圈伤害。

M2 测试替代：自动掷骰，并将两颗最大骰分配至攻击、一颗分配至防御；技能预判和真人拖拽分配尚未接入。

待确认边界：累计伤害与剩余 HP 都完全相同时，当前实现为双方均不淘汰。

## 12. 警报圈、撤离与终局结算

```mermaid
flowchart TD
    A["回合开始"] --> B{"当前是否为第10至12回合"}
    B -- "否" --> C["跳过警报伤害"]
    B -- "是" --> D["所有ACTIVE玩家扣10 HP"]
    D --> E{"HP是否小于等于0"}
    E -- "是" --> F["立即战败并掉落物品"] --> Z["失败结算"]
    E -- "否" --> G["检查上一回合撤离请求"]
    C --> G
    G -- "存在有效请求" --> H["玩家状态改为 EXTRACTED"] --> Y["成功结算"]
    G -- "不存在" --> I["继续本回合"]
    I --> J{"回合结果时是否位于撤离点"}
    J -- "否" --> K["不能呼叫撤离"]
    J -- "是" --> L["玩家主动呼叫白鸽接应"]
    L --> M["记录请求回合，消耗1个完整回合"]
    M --> N{"是否已是第12回合末"}
    N -- "是" --> O["无法进入下一回合完成接应"] --> Z
    N -- "否" --> P["进入下一回合开始结算"] --> A
    K --> Q{"第12回合是否结束"}
    Q -- "是" --> Z
    Q -- "否" --> P
```

终局状态：

| 状态 | 触发条件 | 资产结果 | 结算结果 |
|---|---|---|---|
| `EXTRACTED` | 在撤离点呼叫接应，经过一回合且回合开始时仍存活 | 统计背包物品及总价值 | 成功 |
| `DEFEATED` | 战斗或警报圈使玩家战败 | 未销毁物品掉落在节点 | 失败 |
| `TIMED_OUT` | 第 12 回合结束仍未完成撤离 | 当前局资产判定损失 | 失败 |
| `ACTIVE` 提前结束 | 其他玩家均离场或战败，仅剩一人 | 尚未冻结 | 待确认 |

结算页至少展示：成功/失败、原因、最终回合、剩余 HP、背包物品数、战利品总价值，并提供“返回码头”和“再来一局”。
