## 已确认规则

- 启动后使用 `wx.login` 验证当前微信身份；同一小游戏 AppID + OpenID 对应同一账号。每次冷启动重新验证微信身份，不直接凭上一个微信用户的缓存登录态进入账号。
- 首次账号资料页提供可选的微信原生头像昵称授权按钮。拒绝授权、接口不支持或未返回可用昵称时，显示默认黑桃头像，玩家自行输入游戏昵称。微信昵称也需要通过同一服务端校验后才能保存。
- 本轮昵称限制为 2–16 个汉字、英文字母、数字或下划线，NFKC 规范化后校验；拒绝控制字符、不可见字符和官方保留称谓。再通过微信 `msg_sec_check` 的资料场景检查。审核服务不可用时不能跳过审核发布。
- 仅使用 OpenID 绑定账号，不采集手机号、位置、性别、地区、通讯录、UnionID。微信返回的 session_key 立即丢弃。客户端仅获得游戏账号、游戏登录凭证、头像昵称和业务资产，不获得 OpenID 或微信密钥。
- 礼包只在第一次创建账号的事务中发放：`wp_006`、`ar_001`、`sk_001` 各 1 张，物资 0，金币 0。礼包定义在 `functions/heisino-account/starter.json`，调整配置不会给老账号重复补发。
- 战备只允许带入拥有的武器、防具和技能，最多 4 张（按张数，不按堆叠格数）。可带同一卡多张，前提是数量足够。匹配等待/取消不扣仓库，真正开局时一次性扣除带入物，写入本局物品实例。
- 普通测试匹配与“单人测试·立即开始”都使用正式账号资产。目前仍由界面模拟补齐两名机器人，机器人移动和现有自动战斗已经改由服务端执行。本次没有实现真人多人匹配。
- 成功撤离：剩余带入物和搜到的物资原样回仓，价值只展示，不额外兑换金币。失败/超时/主动放弃：本局携带及搜到的物品不返还，仓库未携带资产保留。场上仅剩自己仍需前往撤离点，不自动获胜。
- 武器、防具不再有耐久字段、消耗或耐久销毁规则。旧卡面图片与 OCR 审计资料可能仍含旧版印刷文字，美术资源应在下一轮卡牌迭代中同步替换。
- 仓库、战备背包与局内背包按同一卡牌每格最多 99 张显示；100 张显示为相邻的 99 + 1 两格。仓库不限格，局内背包仍为 10 格。每次从仓库放入/取下或局内拖拽拾取/丢弃操作处理 1 张，角标显示当前格数量。服务器仍按每张物品独立实例保存，堆叠是显示与容量计算规则。
- 每个账号只能有一局未完成的对局。返回游戏优先恢复该局；中断满 10 分钟判负，以服务端最后联系时间为准。在后台期间暂停本轮操作计时，恢复时保留剩余时间和已曝光进度。未收到正常后台通知时，超过 30 秒无联系视为中断并补偿离线计时。
- 10 分钟截止是逻辑截止时间；数据库最终落盘在下次登录/恢复/请求时触发，记录的失败发生时间仍是截止时刻。当前未增加周期扫描任务。

## 服务端结构与一致性

新增 HTTP 云函数 `heisino-account`，网关路径 `/api/account`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 仅检查服务可启动，不代表微信登录已验收 |
| POST | `/login` | 用临时 code 向微信验证身份并签发游戏会话 |
| GET | `/me` | 读取本人账号、恢复对局或返回最近结算 |
| POST | `/profile` | 保存首次头像昵称资料，包含昵称审核 |
| POST | `/start` | 校验带入数量、扣仓库、服务端建局 |
| POST | `/game` | 移动、观察、拾取、丢弃、关闭搜索层、离开、撤离、放弃 |
| POST | `/heartbeat` | 刷新权威状态并推进到时阶段 |
| POST | `/suspend` | 标记进入后台 |
| POST | `/resume` | 恢复或判定超过 10 分钟失败 |
| POST | `/acknowledge` | 按 `settlementId` 标记对应结算已查看。旧版对局兼容无 ID 确认 |

除登录和健康检查以外均需要 `Authorization: Bearer <游戏会话>`。玩家身份从已校验会话解析，不接受客户端传入的账号 ID/玩家 ID 作为权限依据。游戏会话随机生成，服务端只保存散列，默认有效期 7 天。

`/start` 必须携带 `requestId`、`cardIds` 和模式（`STANDARD`/`SINGLE_TEST`）。`/game` 必须携带 `gameId`、`turn`、`requestId`、`action`。客户端只提交操作意图，不能提交最终背包、金币、胜负或随机种子。未曝光物资种类和随机数状态不下发。

账号文档保存在 `heisino_accounts`：身份、资料、数量、登录态散列、未完成对局、最近结算及最近 100 条流水索引。完整资产流水保存在 `heisino_asset_ledger`。礼包、扣仓、返仓和对应流水在数据库事务内提交；使用文档版本校验避免并发覆盖。每局只产生一次带入流水、一次结算流水。

两个集合均应设置为客户端不能直接读写，只允许服务端通过环境级凭证访问。旧 `/api/search` 保留兼容，不会把其独立测试物品转为账号资产；新版账号对局使用 `/api/account` 的统一权威状态。

前端断网不会切换为可写账号资产的本地模拟。写操作串行发送；网络重试复用同一请求 ID，状态冲突时刷新服务端快照。

## 构建与本地验证

```bash
npm run account:build
npm run check
npm run account:package
```

`account:build` 将共享规则、战斗、背包工具和卡牌目录复制到该云函数的 `runtime/`，生成可独立部署的目录。生成目录不提交版本库；每次规则或卡牌更新后重新构建。测试同时覆盖领域模型、Canvas 端资料拒绝路径、仓库到开局交互和实际本地 HTTP 链路。

`account:package` 生成 `output/deploy/heisino-account-20261103.zip`，包含锁定依赖清单和所有运行时规则，可作为控制台上传包。源码方式部署命令为 `tcb fn deploy heisino-account --httpFn --path /api/account --runtime Nodejs20.19 --install-dependency true`；部署后应确认 `runtime/` 已完整进入云端包。ZIP 不包含任何密钥。

后续推荐执行 `npm run account:deploy`：脚本先构建运行时，再安全读取并保留账号函数现有环境变量；首次部署仅在缺少数据库凭证时复用当前搜索函数的环境级凭证。临时配置位于系统临时目录，权限受限，并在执行结束时删除；控制台输出仅包含变量名和脱敏结果。配置好 AppSecret 后再运行 `npm run verify:account:production`；`WECHAT_EXCHANGE_REACHABLE` 也只表示无效 code 到达微信身份交换接口，不表示真实微信账号或昵称审核已经验收。

`node scripts/inspect-account-acceptance.js <游戏账号ID>` 可只读核查指定账号的昵称、默认/自定义头像状态、资产数量及最近流水和结算摘要。必须明确指定一个账号，不扫描玩家列表，不输出 OpenID、登录凭证、密钥或完整对局状态；不能用此只读检查代替手机上的交互验收。

`node scripts/verify-wechat-nickname.js <游戏账号ID> <拟用昵称>` 可对已经完成真实微信登录的指定账号执行一次本机出网的微信内容审核诊断。密钥与 OpenID 仅在内存中用于官方接口，不记录到源码或日志；输出只包含接口路径、HTTP 状态、微信数字错误码及审核建议，不修改账号或资产。若微信要求出口 IP 白名单，本机结果不代表云函数出口已获准。

`npm run server` 的账号服务使用内存存储，仅供本地联调，重启会清空。真实存档必须使用 CloudBase 云函数。本地服务也需要真实微信 AppSecret 才能调用微信，不提供可在生产启用的假登录或跳过审核开关。

## 真机验收

- 首次打开：登录后显示建号页，授权微信资料可填入头像昵称；拒绝后默认头像可见，自填合法昵称后继续。
- 空昵称、非法字符、保留称谓、内容不合规、审核服务失败分别显示明确提示，不能绕过检查进入对局。
- 仓库仅有礼包三张卡、金币 0。关闭后重新进入仍为同一账号，不重复发礼包。
- 更换微信账号后，不能沿用上一微信账号的缓存仓库。
- 取消匹配不扣物品；实际开局只扣选择物品；单人测试也同样扣除。
- 搜索重复拖拽或请求重试不复制物品；同卡 99/100/199 张分别显示为 99、99+1、99+99+1。
- 成功撤离后仓库增加带出物，金币保持不变；战败/超时后仅损失本局物品；重复打开结算不重复发奖。
- 回到后台几分钟再进，恢复同一局的回合、位置、HP、背包、区域及已曝光物品；超过 10 分钟显示失败并清理未完成状态。
- 武器跨战斗保持存在，不显示耐久或因耐久消失；实际战败仍按掉落规则处理。
