## 当前已实现规则（2026-11-22）

- 启动后使用 `wx.login` 验证当前微信身份；同一小游戏 AppID + OpenID 对应同一账号。每次冷启动重新验证微信身份，不直接凭上一个微信用户的缓存登录态进入账号。
- 首次账号资料页提供可选的微信原生头像昵称授权按钮。拒绝授权、接口不支持或未返回可用昵称时，显示默认黑桃头像，玩家自行输入游戏昵称。微信昵称也需要通过同一服务端校验后才能保存。
- 本轮昵称限制为 2–16 个汉字、英文字母、数字或下划线，NFKC 规范化后校验；拒绝控制字符、不可见字符和官方保留称谓。再通过微信 `msg_sec_check` 的资料场景检查。审核服务不可用时不能跳过审核发布。
- 仅使用 OpenID 绑定账号，不采集手机号、位置、性别、地区、通讯录、UnionID。微信返回的 session_key 立即丢弃。客户端仅获得游戏账号、游戏登录凭证、头像昵称和业务资产，不获得 OpenID 或微信密钥。
- 礼包只在第一次创建账号的事务中发放：`wp_006`、`ar_001`、`sk_001` 各 1 张，物资 0，金币 0。礼包定义在 `functions/heisino-account/starter.json`，调整配置不会给老账号重复补发。
- 战备只允许带入已拥有的武器、防具和技能，总计最多 4 张；当前互动战斗版本最多一件武器、一件防具，技能可重复携带但不能超出实际数量。等待房间和退出不扣仓库，真正开局时一次性扣除带入物并写入本局实例。
- 当前正式单人只有一名真人及房间守卫，不补两名机器人；多人通过 `/lobby` 建房、加入、退出和开局。房间等待有效期为创建后 10 分钟，过期关闭；最后一人退出关闭房间，房主退出由下一位成员接任。当前没有独立的自动排队匹配功能。单人和多人都使用正式账号资产。
- 成功撤离：剩余带入物和搜到的物资原样回仓，不额外兑换金币。战败淘汰、断线满 10 分钟或主动放弃：本局携带及搜到的物品不返还，仓库未携带资产保留。存活的战斗败者按当前战利品规则损失最高售价两件后仍可继续；这不等于整局战败结算。场上仅剩自己仍需前往撤离点，不自动获胜。第 12 回合开始每轮扣 5 HP，没有第 12 回合硬性结束规则。
- 武器、防具没有耐久消耗或耐久销毁规则；新版卡面已于 11 月 12 日发布。原始 OCR 审计材料不作为当前运行规则。技能卡使用后消耗一次，但当前没有数值效果，具体技能效果待定。
- 仓库及战备页面继续以同卡最多 99 张显示堆叠；仓库 100 张拆成 99 + 1，且不限格。战备带入上限仍按张数计算，总计最多 4 张。当前局内背包十格、一格一件，同款不合并；旧局超出十件保留并可翻页丢弃，少于十件后才能继续拾取。每次拖拽处理一张卡或一个实例。
- 每个账号只能有一局未完成对局，返回游戏优先恢复；中断满 10 分钟判负，以服务端最后联系时间为准。单人普通移动和搜索在没有当轮互动战斗状态时可补偿后台/超过 30 秒无联系的离线时间，保留搜索进度；互动战斗及其同轮战利品窗口按截止时间推进，不冻结。多人使用共享时钟，不因个人后台而暂停，其他玩家继续；恢复返回当前有效阶段。
- 10 分钟截止是逻辑截止时间；数据库最终落盘在下次登录/恢复/请求时触发，记录的失败发生时间仍是截止时刻。当前未增加周期扫描任务。

## 服务端结构与一致性

HTTP 云函数 `heisino-account` 是当前账号、单人和多人对局的统一权威入口，网关路径 `/api/account`。下表为网关后的相对路径。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 仅检查服务可启动，不代表微信登录已验收 |
| POST | `/login` | 用临时 code 向微信验证身份并签发游戏会话 |
| GET | `/me` | 读取本人账号、恢复对局或返回最近结算 |
| POST | `/profile` | 保存首次头像昵称资料，包含昵称审核 |
| POST | `/start` | 当前单人 `SINGLE` 开局；保留历史模式兼容 |
| POST | `/lobby` | 列表、建房、加入、退出、房主开局；多人开局事务扣仓 |
| POST | `/game` | 移动、搜索、拾取、丢弃、离开、放弃，以及掷骰/摆放/准备/技能使用；撤离由当前大回合结束时自动判定 |
| POST | `/heartbeat` | 刷新权威状态并推进到时阶段 |
| POST | `/suspend` | 标记进入后台 |
| POST | `/resume` | 恢复或判定超过 10 分钟失败 |
| POST | `/acknowledge` | 按 `settlementId` 标记对应结算已查看。旧版对局兼容无 ID 确认 |
| POST | `/shop` | 已建号、无等待房且无未完对局时查询目录、整单买卖 |

除登录和健康检查以外均需要 `Authorization: Bearer <游戏会话>`。玩家身份从已校验会话解析，不接受客户端传入的账号 ID/玩家 ID 作为权限依据。游戏会话随机生成，服务端只保存散列，默认有效期 7 天。

当前客户端 `/start` 携带 `requestId`、`cardIds`、`mode: "SINGLE"`、`combatVersion: 1`；`STANDARD`/`SINGLE_TEST` 仅历史兼容。`/lobby` 的 `op` 为 `list/create/join/leave/start`，写操作需 `requestId`；加入和建房携带战备与版本，开局核对全员版本，过低返回 `409 PLAYER_VERSION_TOO_LOW`，不扣仓。`/game` 携带 `gameId`、`turn`、`requestId`、`action`（放弃按对局 ID 处理，不受旧回合限制）。客户端只提交操作意图，不能提交最终背包、金币、胜负或随机种子。未曝光物资种类和随机数状态不下发。

账号文档保存在 `heisino_accounts`：身份、资料、数量、登录态散列、未完成对局、最近结算及最近 100 条流水索引。完整资产流水保存在 `heisino_asset_ledger`。礼包、扣仓、返仓和对应流水在数据库事务内提交；使用文档版本校验避免并发覆盖。每局只产生一次带入流水、一次结算流水。

账号、资产流水以及 `heisino_match_rooms` 多人房间集合均只允许服务端读写，发布记录已核对为 `ADMINONLY`。旧 `/api/search` 保留兼容，不会把其独立测试物品转为账号资产；新版账号对局使用 `/api/account` 的统一权威状态。

前端断网不会切换为可写账号资产的本地模拟。资产写操作通过请求队列发送，网络重试复用同一请求 ID；移动可绕过慢心跳，战斗摆放通过递增版本保护允许并发，状态冲突时刷新服务端快照。

商店 `op: "list"` 返回 `profile`、`revision`、`catalog`。目录每项有 `cardId`、`grade`、`sellPrice` 和 `buyPrice`（不上架时为 `null`）。`op: "buy"` 或 `"sell"` 还需传 `cardId`、正整数 `quantity`、确认时的 `unitPrice` 和 `requestId`。服务端用当前报价计算成交额；过期报价、库存或余额不足返回 409 且不写资产。成功返回成交回执 `trade`。金币、卡牌数量和流水同事务写入，按账号和请求号查完整流水；即使旧流水移出账号摘要，同单重试仍只成交一次。同请求号更换内容会被拒绝。客户端把待确认的订单按账号保存，超时或冷启动后用原请求号重试。

新版买卖请求使用 `{ op, requestId, items: [{ cardId, quantity, unitPrice }] }`，同种卡汇总为一个条目，回执在 `trade.items` 中列出所有条目。服务端校验每张卡的报价、可售条件和数量，再校验整单金额，任一条失败则整单拒绝。一次成功订单对应一笔流水，重试允许条目顺序变化。旧请求仍可传顶层单卡字段，并收到原格式回执。

`profile.assetValue` 是金币与全部仓库卡牌的估值之和。单人及多人 `activeGame.backpackAssets` 返回 `initial`、`current` 和 `change`，仅计算玩家持有卡牌，包含已装备卡。旧对局通过扣仓流水恢复基准；无历史流水时仅显示当前资产。成功撤离仍原样返仓，不直接发金币。

`account:build` 将共享规则、战斗、背包工具和卡牌目录复制到该云函数的 `runtime/`，生成可独立部署的目录。生成目录不提交版本库；每次规则或卡牌更新后重新构建。测试同时覆盖领域模型、Canvas 端资料拒绝路径、仓库到开局交互和实际本地 HTTP 链路。

`account:package` 当前脚本输出仍固定命名为 `output/deploy/heisino-account-20261103.zip`；文件名不能证明源码日期，应按待发布 Git 提交重新构建、记录校验值并核对打包内容。包包含锁定依赖和运行时，不含密钥。已有函数的后续更新优先按[CloudBase 发布与验收](CloudBase发布与验收.md)使用代码更新保留现有环境配置；部署后确认 `runtime/` 完整。

后续推荐执行 `npm run account:deploy`：脚本先构建运行时，再安全读取并保留账号函数现有环境变量；首次部署仅在缺少数据库凭证时复用当前搜索函数的环境级凭证。临时配置位于系统临时目录，权限受限，并在执行结束时删除；控制台输出仅包含变量名和脱敏结果。配置好 AppSecret 后再运行 `npm run verify:account:production`；`WECHAT_EXCHANGE_REACHABLE` 也只表示无效 code 到达微信身份交换接口，不表示真实微信账号或昵称审核已经验收。

`node scripts/inspect-account-acceptance.js <游戏账号ID>` 可只读核查指定账号的昵称、默认/自定义头像状态、资产数量及最近流水和结算摘要。必须明确指定一个账号，不扫描玩家列表，不输出 OpenID、登录凭证、密钥或完整对局状态；不能用此只读检查代替手机上的交互验收。

`node scripts/verify-wechat-nickname.js <游戏账号ID> <拟用昵称>` 可对已经完成真实微信登录的指定账号执行一次本机出网的微信内容审核诊断。密钥与 OpenID 仅在内存中用于官方接口，不记录到源码或日志；输出只包含接口路径、HTTP 状态、微信数字错误码及审核建议，不修改账号或资产。若微信要求出口 IP 白名单，本机结果不代表云函数出口已获准。

`npm run server` 的账号服务使用内存存储，仅供本地联调，重启会清空。真实存档必须使用 CloudBase 云函数。本地服务也需要真实微信 AppSecret 才能调用微信，不提供可在生产启用的假登录或跳过审核开关。

## 新环境初始化与后续发布

现有上海环境已有账号、卡牌、搜索和多人房间发布记录，以下初始化步骤用于新环境或配置核对，不要求重建已有账号/集合。后续业务更新必须执行独立的发布回归、公网验证及权限检查。

1. 在项目根目录运行 `npm run account:build`。首次创建 `heisino-account` 时需要完整运行时和依赖；已有函数按发布流程更新代码，不要只上传 `index.js`。
2. 在 CloudBase 控制台该函数的环境变量中填写以下内容；不要发到聊天或写入源码：

| 变量 | 内容 |
|---|---|
| `WX_APPID` | `wxac0dd152fc261ffd` |
| `WX_APPSECRET` | 该小游戏后台的 AppSecret |
| `CLOUDBASE_ENV_ID` | `cloud1-d5ghcmrajdca722b5`；也可使用运行时的 `SCF_NAMESPACE` |
| `CLOUDBASE_APIKEY` | 当前环境的服务端数据库访问 Key，需支持账号、资产流水和多人房间集合的事务读写 |

3. 函数配置刻意没有 `envVariables` 字段，防止后续 CLI 部署整体覆盖控制台密钥。不要为了方便把实际密钥写入 `cloudbaserc.json`。
4. 确认 HTTPS 网关映射 `/api/account`，并允许 `GET`、`POST`、`OPTIONS`。配置稳定出口 IP 到微信后台 IP 白名单（如当前微信接口配置要求），保证能调用微信 access token 和昵称审核接口。
5. 在微信小游戏后台保留现有 API 域名的 request 合法域名配置，以及卡面 CDN、微信头像实际使用的域名配置。原生授权返回值与头像加载必须在真机检查，不能用“开发工具不校验域名”作为验收结论。
6. 在后台对应的隐私说明中如实配置本次用户资料用途：可选头像与昵称用于游戏身份展示；拒绝资料授权不影响使用默认头像和自填昵称。确认账号当前具有小游戏用户信息接口和内容审核接口的使用权限。若审核接口返回权限错误，应修复后台权限，不能以“格式合法”替代内容审核。
7. 涉及共享规则、卡牌或掉落表时，核对账号、卡牌和兼容搜索三个函数的受影响范围；卡面资源按当前目录版本发布。当前卡库为 51 个有效 ID、50 张新版卡面，不按 11 月 3 日旧数量验收。

## 当前真机验收范围（尚待补齐逐项记录）

- 首次打开：登录后显示建号页，使用默认头像、自填合法昵称后继续。可选微信头像授权单独列为暂缓，不视为已验收。
- 空昵称、非法字符、保留称谓、内容不合规、审核服务失败分别显示明确提示，不能绕过检查进入对局。
- 仓库仅有礼包三张卡、金币 0。关闭后重新进入仍为同一账号，不重复发礼包。
- 更换微信账号后，不能沿用上一微信账号的缓存仓库。
- 多人建房、加入、退出不扣物品；房主开局后各账号只扣一次已选战备；正式单人也同样扣除。
- 搜索重复拖拽或重试不复制物品；局内同款一格一件，十格满拒绝拾取，丢弃后才可补入。仓库同卡 99/100/199 张分别显示为 99、99+1、99+99+1。
- 存活到撤离点当轮行动结束后自动撤离，带出物返仓，金币不因撤离增加；战败淘汰/断线到期/放弃只损失局内物品；重开结算不重复返仓。另核对商店整单买卖、取消、超时冷启动重试与换号隔离。
- 单人普通移动/搜索在没有当轮互动战斗状态时切后台可补偿暂停；战斗及同轮战利品按截止推进。多人切后台时他人继续，重进恢复当前回合/战斗/战利品；满 10 分钟显示个人失败且不阻塞其他玩家。
- 武器跨战斗保持存在，不显示耐久或因耐久消失；实际战败仍按掉落规则处理。
