# M1 本地规则原型说明

版本：0.1.0
状态：已完成并由 M2 完整流程测试包承接；本文保留为里程碑记录

## 1. 本阶段目标

M1 是运行在微信开发者工具中的本地三人规则原型。玩家 1 由真人控制，玩家 2、玩家 3 使用随机移动和自动战斗，目的是尽快验证一局内最重要的操作与状态衔接，不代表最终联机架构或正式视觉效果。

已形成的闭环：

```text
回合开始
→ 第 10 回合起结算警报圈伤害
→ 隐藏提交移动
→ 同时公布移动轨迹
→ 单人搜索 / 两人战斗 / 三人分流
→ 显示、拾取或丢弃物资
→ 结束回合
→ 最多推进至第 12 回合
```

## 2. 已实现规则

- 5×5 节点地图；玩家只能停留或移动到上下左右相邻节点。
- 真人提交前看不到机器玩家的选择；提交完成后统一结算并显示轨迹。
- 未在移动倒计时内提交时自动停留。
- 单人节点进入搜索；第一次点击显示物资，第二次点击拾取。
- 两人同节点自动进行最多 3 个小回合的骰子战斗。
- 三人同节点随机两人战斗、一人搜索，原房间物资随机拆分给两条处理线。
- 背包上限 8 格；装备占格；满包拒绝拾取且物资留在房间。
- 背包物品可拖到右下角丢弃，丢弃物保留在当前节点。
- 武器耐久为 2，每完成一场战斗消耗 1；耗尽后销毁。
- 第 10、11、12 回合开始时，存活玩家立即扣除 10 HP；HP 为 0 时立即战败。
- 战败玩家携带物品变为当前节点的待拾取物。
- 音频保持全局静音，仅保留稳定事件接口。

## 3. 原型临时规则

以下规则用于让 M1 可运行，但必须由 PMO/策划确认后才能成为正式规则：

| 编号 | 未冻结边界 | M1 临时处理 |
|---|---|---|
| T-01 | 55 秒内移动和搜索各占多少时间 | 移动选择 15 秒，总回合 55 秒；提前提交可获得更多搜索时间 |
| T-02 | 三人节点有奇数件物资时如何“一半一半” | 多出的一件通过随机数分给战斗线或搜索线 |
| T-03 | 累计伤害和剩余 HP 都相同后的胜负 | 判定完全平局，双方都不淘汰 |
| T-04 | 战败后具体可掠夺件数及其余资产去向 | 战败者全部未销毁物品掉落在当前节点，胜者获得搜索权限 |
| T-05 | 武器购买价缺失时的经济价值 | 战斗倍率可用；经济价值暂按 0，卡牌状态保持 `BLOCKED` |
| T-06 | 机器玩家搜索策略 | M1 机器玩家不自动拾取物资，只用于制造移动与战斗遭遇 |
| T-07 | 第 12 回合后的撤离与资产结算 | 仅进入 `GAME_OVER`，不进行正式收益结算 |

## 4. 真人验收清单

- [ ] 项目可被微信开发者工具识别为小游戏并正常编译。
- [ ] 画面为横屏，5×5 地图和右侧信息面板没有明显遮挡。
- [ ] 只能点击当前节点或上下左右相邻节点，不能斜向移动。
- [ ] 移动后能看到三名玩家的移动轨迹。
- [ ] 物资第一次点击显示名称和价值，第二次点击进入背包。
- [ ] 背包物品可拖拽到右下角丢弃区。
- [ ] 同节点时能看到战斗结果或三人分流结果。
- [ ] 第 10 回合开始发生警报圈扣血。
- [ ] 第 12 回合结束后停止推进并提示进入结算。

## 5. 自动化验证

当前自动化用例覆盖：卡牌配置投影一致性、合法移动、超时停留、两段式拾取、满包拒绝、警报圈、三人分流、战斗回合上限、装备耐久和 HP 归零战败。

执行命令：

```bash
npm test
```
