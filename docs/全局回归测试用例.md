# 全局回归测试用例

使用 Node.js 22 或更高版本。全量入口执行语法检查和 `tests/` 下所有 `*.test.js`，含接口、服务端规则、Canvas 触控和静态资源。模拟账号、可控时钟和本机回环服务支持重复运行。每轮的 JSON 报告含实际用例、失败数、覆盖率和未覆盖分支行。

```bash
npm run test:regression
npm run test:regression -- --rounds 5
npm run test:regression -- --update-cases
```

默认报告保存在 `coverage/regression/`。可用 `--report-dir` 指定报告目录，用 `--concurrency 1` 顺序运行同一轮的测试文件。索引按真实运行的用例与测试文件内容生成，失败、跳过或索引不一致都会使命令失败。GitHub Actions 在推送和拉取请求时执行一轮。工作流进入默认分支后可手动触发五轮。[GitHub 手动运行工作流说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

## 每次迭代的更新规则

1. 功能改动时更新对应行的入口、正常路径、失败、超时、重试、恢复与预期。涉及多个模块时补齐联动分支。
2. 将新增或变更行为写成能复现的用例。执行 `npm run test:regression -- --update-cases`，把索引和业务改动放在同一提交或拉取请求。
3. 发布前跑五轮全量回归。出现失败时先记录触发条件、修复、复测，再继续后续轮次。
4. 微信原生授权、真实域名、CloudBase 事务权限、手机帧率和多机视觉属于真机验收。测试报告还列出未加载文件与未覆盖行，用来指导补测。
5. 服务端、接口或云端共享数据变更按 [CloudBase 发布与验收](CloudBase发布与验收.md)部署。公网冒烟测试单独记录大厅预检、接口鉴权、卡牌目录、受影响的业务响应及数据库权限。
